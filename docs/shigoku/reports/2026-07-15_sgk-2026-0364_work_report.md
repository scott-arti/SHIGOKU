# 作業報告書: SGK-2026-0364 Derived Task Admission Policy Cleanup and Coverage-Critical Consolidation

## 完了ステータス
derived task admission policy の整理と、coverage-critical 判定の共通化を実施した。

## 原因
`MasterConductor._add_tasks()` は `recon_result` と `react` / `replan` のような自己増殖しうる source を同じ `max_derived_tasks_per_session` で扱っていた。

そのため、Recon 結果から正当に fan-out した attack task 群まで derived cap の対象になり、後追いで `SCN06` / `meta_observability` / `coverage_backfill` を個別 exempt する構造が増えていた。

## 変更内容
| ファイル | 変更 |
|----------|------|
| `src/core/engine/master_conductor.py` | derived cap を source-aware 化し、`recon_result` / `dynamic_recipe` / `pending_fuzz` を generic cap の対象外に変更。SCN06 blanket exempt を削除し、recon enqueue ログを「生成数」と「実キュー投入数」で混同しない形に修正。 |
| `src/core/engine/task_pruning_policy.py` | coverage-critical task 判定と derived-cap source 判定を shared helper として集約。 |
| `src/core/engine/task_queue.py` | queue pruning 保護判定を shared helper に寄せて重複を削減。 |
| `src/core/engine/strategy_optimizer.py` | low-value pruning 保護判定を shared helper に寄せて重複を削減。 |
| `tests/core/engine/test_master_conductor_scenario_probes.py` | derived cap regression を新方針へ更新し、`recon_result` は通す一方で `SCN06` が dynamic source からの万能 exempt ではないことを検証。 |

## 検証結果
- `mcp__serena.get_diagnostics_for_file` で `master_conductor.py`, `task_queue.py`, `strategy_optimizer.py`, `task_pruning_policy.py`, `test_master_conductor_scenario_probes.py` の変更箇所を静的確認し、変更箇所に追加の診断エラーがないことを確認。
- `.venv/bin/pytest tests/core/engine/test_master_conductor_scenario_probes.py tests/core/engine/test_task_pruning_policy.py tests/core/engine/test_dynamic_task_queue.py tests/core/engine/test_strategy_optimizer.py -q` を試行したが、実行環境の runner が `bwrap: execvp .../codex: No such file or directory` で失敗し、pytest 実行は blocked。
