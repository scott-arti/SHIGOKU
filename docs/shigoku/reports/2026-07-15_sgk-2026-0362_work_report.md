# 作業報告書: SGK-2026-0362

## 実装内容
- `src/core/conductor/interactive_bridge.py` に `intervention_gate_mode` 正規化 helper と ExecutionSafeguard 用 HITL callback builder を追加した。
- `observe` モードでは endpoint HITL callback が非対話で許可を返し、`InteractiveBridge.ask_for_approval()` を呼ばないようにした。
- `enforce_human_preferred` / `enforce_hitl` では従来どおり `ask_for_approval()` を `asyncio.to_thread()` 経由で呼ぶ。
- CLI が更新する `src.config.settings.intervention_gate_mode` を参照し、preflight 用 `src.core.config.settings.get_settings()` と混同しないようにした。
- `tests/core/test_interactive_bridge_execution_safeguard_hitl.py` を追加し、observe/強制モード/invalid fallback の回帰テストを入れた。

## 判断理由
- 問題はプロンプト表示関数そのものではなく、`observe` が MasterConductor の intervention gate にしか伝わらず、ExecutionSafeguard/RequestGuard の HITL callback が残り続けていた設定境界の不整合だった。
- `observe` の期待値は「HITL を観測のみとして実行を止めず、対話プロンプトを出さない」ため、callback 生成時点で非対話 auto-allow に切り替えるのが根本修正になる。
- 強制モードの既存動作を維持するため、RequestGuard や ExecutionSafeguard の fail-closed ロジックは変更しなかった。
