# SGK-2026-0470 計画 — AI 逐次判断の遅延削減（フル走行の高速化）

## 目的（何を・なぜ）

SGK-2026-0468 part-2 の実走行で、フル自律走行の遅さの主因が定量的に判明: 約1時間で
**LLM 呼び出し186回・思考ループ42ターン**。時間の大半は「ほぼ一手ごとに LLM へ問い合わせる」
ネット往復（各数秒）で占められ、標的応答自体はミリ秒。これが実戦での使い勝手（および
認証付き走査のトークン失効 [[SGK-2026-0469]] との競合）を悪化させている。

## 事実（0468 実走行での観測）

- LiteLLM completion 呼び出し 186 回 / thought_loop ターン 42 回 / 経過 ~54 分（basket 狙い撃ちのつもりが
  クロールで7URLを拾い広く検査）。
- 並列度は負荷で自動低下（7→3）。全通信はプロキシ経由。

## 対象（in scope・候補）

1. 決定論化: LLM に委ねている分類・優先度付けのうち、決定論ロジックで置換可能なものを特定し置換
   （検出精度を落とさない範囲で LLM 往復を削減）。
2. キャッシュ/バッチ: 同型判断のキャッシュ、思考ターンのバッチ化・上限最適化。
3. スコープ制御: 狙い撃ちターゲット時に不要な広域クロール／エンジンを抑制するモード。

## 完了条件（案・実装開始時に確定）

- 代表シナリオでフル走行の LLM 呼び出し回数／総時間を有意に削減し、検出・確定の結果が非回帰
  （confirmed/candidate の質を落とさない）。
- 確定バー5ファイル無改変・token 0・validator 0。

## NOT in scope

- 確定バー5ファイルの改変。
- 検出網羅性を犠牲にした見かけ上の高速化（カーブフィッティング禁止）。
- 認証寿命管理そのもの（[[SGK-2026-0469]]）。
