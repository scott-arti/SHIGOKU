# 実装計画書：CLIマニュアルと実装の同期

## 1. 達成したいゴール（ユーザー視点）
- [x] 利用者がマニュアルを見ると、現在利用できる CLI の入口、引数、モードを実装どおりに確認できること。

## 2. 全体像とアーキテクチャ
- **対象コンポーネント/ファイル一覧:**
  - `src/main.py`: 実行系 CLI `shigoku` の引数定義の正本。
  - `scripts/shigoku_ops_cli.py`: 運用系 CLI `shigoku-ops` のサブコマンドと引数定義の正本。
  - `docs/shigoku/manuals/{USER_MANUAL.md,REFERENCE.md,QUICK_START.md}`: 利用者向け案内。
  - `docs/shigoku/manuals/manual_legacy/2026-07-02_sgk-2026-0337_detailed-command-reference.md`: 詳細コマンド一覧。
- **データの流れ / 依存関係:**
  - argparse 定義と `--help` 出力 -> 詳細コマンド一覧 -> 各利用者向けマニュアルからのリンク

## 3. 具体的な仕様と制約条件
- **入力情報 (Input):** `shigoku --help`、`shigoku-ops ... --help`、各 argparse 定義。
- **出力/結果 (Output):** 実装済みのコマンドのみを案内し、必須・選択式の引数を誤記なく記載する。
- **制約・ルール:**
  - report / session / validate は `shigoku-ops` を優先する。
  - 未コミットの無関係な変更を戻さない。
  - 文書更新後は更新日同期と文書検証を実行する。

## 4. 実装ステップ（AIに指示する手順）
- [x] ステップ1: 現行マニュアルと CLI 定義を照合し、削除済みオプションと未記載コマンドを特定する。
- [x] ステップ2: 詳細コマンド一覧と参照元マニュアルを最小限更新する。
- [ ] ステップ3: リンク、`--help` 出力、SHIGOKU 文書検証で確認する（既存台帳参照切れ2件の解消待ち）。

## 5. 既知のリスクと次回の申し送り（Backlog / 技術的負債）
- 実行系 CLI は引数数が多いため、将来の引数追加時にマニュアルの更新が漏れるリスクがある。CLI 定義と `--help` を根拠に定期的に照合する。
