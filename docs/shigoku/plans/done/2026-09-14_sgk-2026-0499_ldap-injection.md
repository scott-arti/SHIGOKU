# SGK-2026-0499 計画 — LDAP インジェクション（認証バイパス）を実対象で本物確定（◎）

## 背景・事実（偵察で実測）

既存 `attack/ldap_tester.py` は **完全なプレースホルダ**（`_test_payload` がリクエストを送らず空結果を返す）
＝未配線。ペイロード表とエラーパターンの参照のみ有用。確定は他クラス同様、新エンジンで新設する。

実対象：**SKF `ldap-injection`**（Flask・:5000・実 LDAP バックエンド。`POST /login` が
`search_filter = "(&(cn="+username+")(sn="+password+"))"` を文字列連結して `search_s` する）。実測：
- コントロール（`nouser123`/`nopass123`）→ 応答本文 "Wrong identity provided."
- 注入（`username=*&password=*`）→ 応答本文 "You are now admin user!"（＝正当な資格情報なしの認証バイパス）

## 対象（完了契約）

SKF `ldap-injection` を実対象で **機械フロア＋実再現＋実 poc_judge の完全3ゲート**で ◎。確定は**in-band
差分**（メタ文字を含まないリテラル資格情報は失敗×LDAP メタ文字は成功）。成功印は task 由来
（`ldap_success_marker`）優先、無ければ**2 コントロールで安定するベースラインに対し注入応答にだけ現れる
特徴行を自動導出**（製品固有文字列をエンジンにハードコードしない）。非破壊（読み取り専用の検索）。

## 実装方針（新設1＋承認済み凍結2）

1. **`injection/smart_ldap_injection.py`（非凍結・新規）**: `SmartLDAPInjectionHunter`。
   ①負のコントロール（ランダムリテラル×2）②LDAP メタ文字ペイロード（`*`/`*`、`*)(cn=*))(|(cn=*` 等）で
   成功印の差分を確定。`self._client` seam・**マーカー中心スニペット**（先頭切り詰め回避）・コントロールは
   同一バイト領域を切り出し（差分は同じ領域の両側で提示）・auth は poc マスク／evidence 保持・
   ldap_evidence／ldap_replay／差分2ステップ poc。
2. **`payout_grade.py`（凍結・承認）**: `_LDAP_METACHAR_PATTERN`（`*`／`)(`／`(|`／`(&`）＋
   `_MARKER_CATEGORIES["ldap_injection"]="ldap_injection_confirmed"`＋発火分岐（request_url 非空＋payload に
   メタ文字＋success_marker 非空＋injection 2xx＋marker が injected_body 実在＋control_body 非実在・
   fail-closed）。finding.py に `VulnType.LDAP_INJECTION`。
3. **`sealed_reproduction_checker.py`（凍結・承認）**: `_check_ldap_replay`（fresh リテラルのコントロール×
   確定済みメタ文字ペイロードを form 再送し、成功印が注入応答に再出現＋コントロールに非出現→matched）。

## poc_judge 対策（[[poc-judge-raw-evidence]]）

差分型は**両側（リテラル失敗×メタ文字成功）を同じ領域で見せる**のが必須（NoSQLi の教訓を先取り適用）。
マーカー中心スニペットで成功印が snippet に載ることを保証。

## 完了条件

1. 実 SKF `ldap-injection` で実 `SmartLDAPInjectionHunter.execute` が差分で自走検出→payout_grade=True/
   ldap_injection_confirmed。
2. 実 `SealedReproductionChecker` が fresh コントロール×メタ文字で差分を再観測→matched→CONFIRMED。
3. 本物の poc_judge（実 LLM）で is_real=True・has_actual_impact=True・counter_evidence=False。
4. 製品非依存 fixture の新規テスト緑（engine 差分・両側 poc・非脆弱で不確定・コントロールはメタ文字なし・
   provided marker／payout_grade fail-closed 各否定側／sealed matched・mismatched・not_run）。
5. 凍結3 exit 0。製品トークン0・秘密値非露出・回帰ゼロ。

## NOT in scope

- ブラインド（真偽ベース・時間ベース）LDAP 注入・属性開示の網羅・LDAP 以外のディレクトリ（AD 固有）・
  非フォーム（GET/JSON）注入点の一般化は別途。
